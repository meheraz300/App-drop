# 3. FIX THE ADMIN APK UPLOAD SYSTEM

The Admin must be able to upload the original APK reliably.

Implement the following:

### 3.1 Original File Validation

Before uploading:

- Validate the .apk extension.
- Validate that the selected file is not empty.
- Validate the maximum allowed file size.
- Validate APK structure using an appropriate APK validation method.
- Record the original filename.
- Record the exact file size in bytes.
- Calculate the original file's SHA-256 hash.

Do not treat a filename or file extension as proof of APK integrity.

### 3.2 Firebase Storage Upload

- Upload the original binary directly to Firebase Storage.
- Do not rebuild, modify, repackage, or replace the APK.
- Use a unique and predictable Storage path associated with the correct app and version.
- Wait for the upload operation to complete.
- Do not treat an upload-start event as a successful upload.
- Retrieve the uploaded object and verify that it contains the expected original binary.
- Compare the uploaded object's SHA-256 and file size with the original file.

For large APK files, implement an efficient hashing approach that does not unnecessarily freeze the browser or exhaust memory. Use an appropriate incremental SHA-256 implementation or Web Worker where necessary.

### 3.3 Upload Success Conditions

The Admin upload operation is successful ONLY when:

- Firebase Storage upload completes.
- The uploaded file is accessible.
- The uploaded file's SHA-256 matches the original.
- The uploaded file size matches the original.

If any condition fails:

- Mark the upload as failed.
- Do not publish the version.
- Do not create misleading success messages.
- Show a clear error.
- Allow a safe retry.

# 6. IMPLEMENT USER DOWNLOAD INTEGRITY VERIFICATION

Fix the complete User download workflow.

The User must receive the exact binary uploaded by the Admin.

### Download Process

1. User opens a published app version.
2. Application retrieves the correct version metadata from Firestore.
3. Application verifies that the version is published and has valid integrity metadata.
4. Application retrieves the exact corresponding APK from Firebase Storage.
5. Application obtains the downloaded binary.
6. Calculate its SHA-256 hash.
7. Compare the calculated hash with the Admin-verified SHA-256 hash.
8. Compare the downloaded file size with the Admin-recorded file size.
9. Only after both checks pass, allow the file to be saved or downloaded.

### Download Failure Conditions

Reject the download if:

- The APK is missing.
- The Storage path is incorrect.
- The APK belongs to another version.
- SHA-256 does not match.
- File size does not match.
- The file is corrupted or incomplete.
- The version is unpublished.
- Integrity metadata is missing or invalid.

Never silently switch to another APK.

Never display a successful download message before verification is complete.

### Download Filename

Use the correct original filename or a safe filename derived from the verified version metadata.

Do not change the APK binary itself just to change its filename.

### Download Integrity UI

Provide clear status messages:

- Preparing download
- Downloading APK
- Verifying file integrity
- Verification successful
- Download failed
- SHA-256 mismatch
- File size mismatch
- APK unavailable

Preserve the existing visual design and use its existing UI components.
